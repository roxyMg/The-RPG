# 派生输入窗口 v0.1

## 目的
通过每招的输入时间窗口控制连招节奏，保留招式派生图、现有 FSM 和 Animator。窗口只决定是否缓存下一招，不决定伤害时刻或立即取消当前攻击。

## 当前规则
Rapier_Move_01、02、03 都明确保存 branchWindowEnabled = 1、branchWindowStart = 0.2、branchWindowEnd = 0.6。计时起点是进入 C# 攻击状态，而不是动画开始播放。
时间区间含开始和结束边界；输入按帧采样。窗口外输入不会进入缓存，不会在窗口打开时自动重放，也不会清掉已有的有效缓存。
窗口内依旧同帧 F 优先，最后有效输入优先。无对应派生的输入不清空已有缓存。
关闭窗口后已有缓存保留，直到 CurrentStateTrigger 请求原有帧末衔接。每次接入新招式重新计时，中断不遗留缓存。
第三段虽然配置窗口，但没有后续招式，所以仍不能派生。

## 配置入口
Assets/Data/Combat/Attacks/Rapier/Rapier_Move_01.asset（以及 02、03）：
- Branch Window Enabled：开启时间限制。未配置窗口的其他招式、旧固定连段维持整段缓存行为。
- Branch Window Start：从进入攻击状态起算的开始秒数，目前 0.2。
- Branch Window End：结束秒数，目前 0.6。
负数和倒置区间会在读取属性时得到非负、结束不早于开始的区间；建议仍在 Inspector 配置正确的区间。

## C# 与 Unity 知识
Attack_MoveDefinition 的 SerializeField 字段让策划在 Inspector 编辑规则；只读属性供状态读取。PlayerAttackState 在 Enter 保存 Time.time，每次判断时用 Time.time 减去起点得到本招经过的秒数。
Time.time 是缩放后的游戏时间，暂停时不继续计时。这里不跟随 Animator.speed：将来修改动画速度，需要同步调整窗口或升级为动画进度驱动。
QueueNextAttack 中窗口外的 return 仅结束本次缓存处理；Update 仍继续处理原有动画结束事件。F 同样必须同时满足窗口开放和存在后续招式才能写缓存。
UI_AttackDebug 只读时间与窗口状态，区分“窗口外输入”和“无对应派生”。增加两行后面板高度由 210 调为 250。

## 当前动画时序限制
Player_Attack_0 的结束事件约在动画时间 0.714 秒；Player_Attack_1 在 0.25 秒；Player_Attack_2 在 1 秒。
因此在当前播放速度下第二段实际可输入时间很短，约为进入状态后 0.2～0.25 秒，且会受到 Animator 进入延迟及输入帧率影响。三个招式配置仍统一为用户指定的 0.2～0.6，没有修改动画或结束事件。

## 验证记录
实际写入六个文件，与已检查候选内容哈希一致。采用项目 Unity 编译参数进行脚本编译：0 错误、6 项既有警告。311 项隔离断言通过，包含此前功能回归、边界输入、有效缓存保留、无效输入不自动重放、重新计时和窗口开关。
隔离检查使用 Unity 类型适配器，不运行真实物理、Animator 或 Unity 协程。完整 Play Mode 手动验证仍需要进行。

## Unity 手动验证
1. 等待编译完成并检查 Console，进入 SampleScene 的 Play Mode。
2. 第一段在 0.2 秒前按左键或 F：面板显示窗口外输入，缓存为空；随后不再按键不会自动接下一招。
3. 第一段在 0.2～0.6 秒内按键：左键缓存第二段、F 缓存第三段；等待结束事件衔接。
4. 窗口内先缓存成功，再于 0.6 秒后按其他键：已有缓存保留，按原缓存衔接。
5. 第二段在约 0.2～0.25 秒内按左键可接第三段；F 显示无对应派生。第三段无后续招式。
6. 检查每次派生计时归零；Dash 中断后重新普攻从第一段开始且无残留缓存。
7. 取消某招 Branch Window Enabled，确认该招可整段缓存；完成检查后恢复开启。
8. 查看面板新增两行中文、确认 HUD 与攻击命中表现正常。
