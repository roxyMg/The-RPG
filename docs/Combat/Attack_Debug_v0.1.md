# 攻击派生调试面板 v0.1

## 目的和范围
让策划在 Play Mode 观察招式派生输入与缓存，帮助验证配置。保留现有 FSM、Animator、命中结算和玩家 HUD。

## 实现
- Player_AttackState 提供只读属性，记录最近一次派生输入是否有效；无对应派生的 F 输入仍保留之前有效的缓存。
- UI_AttackDebug 挂在 SampleScene 的 Player 上，使用 OnGUI 在右上角显示当前招式、左键/F 可用派生、最近派生输入、缓存招式与衔接状态。
- Show Debug 控制显示；Editor Only 默认启用，仅在编辑器 Play Mode 显示。
- 面板在 LateUpdate 读取状态，不读取或消费攻击输入，不更改 FSM、招式或弹药。只读属性允许观察数据而不允许 UI 写入。
- 最近派生输入在每次进入攻击状态时重置。这里只记录攻击期间的派生输入；空闲时不会记录所有按键。
- 已提交帧末衔接可能只持续一帧，面板不保证能肉眼捕捉该短暂状态。

## 验证
实际写入后的四个文件均与候选哈希一致。使用项目 Unity 编译参数完成全部游戏脚本编译：0 错误，6 项既有警告。275 项隔离断言通过，覆盖派生、失效输入保留缓存、关闭显示仍可派生，以及此前战斗功能。
隔离检查不运行 Unity 物理、Animator 或真实协程，也不能确认实际字体和画面布局。当前 Editor.log 的有限扫描未发现匹配的编译错误；这不替代 Unity Console 与 Play Mode 验证。

## Unity 验证步骤
1. 等待 Unity 导入，确认 Console 无新增错误，打开 SampleScene 并进入 Play Mode。
2. 第一段攻击期间按左键：查看缓存 Rapier_Move_02；按 F：查看缓存 Rapier_Move_03。
3. 第二段按 F：应显示无对应派生；若之前已经按左键缓存第三段，缓存仍保留。
4. 核对等待动画结束与实际下一招一致，攻击结束后显示非攻击状态。
5. 在 Player 的 UI_AttackDebug 组件取消 Show Debug，确认面板消失，攻击仍正常。
6. 确认右上角中文完整、布局合适，玩家 HUD 正常。
