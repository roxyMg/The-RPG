# 杀伤弹奖励规则 v0.2

## 问题与目的
原规则为处决伤害生效回一发，处决击杀额外回一发，其他击杀每名回一发。枪反耗一发后处决击杀能净赚一发，且未击杀也收回枪反成本。
本版降低补给频率，保留处决击杀作为较高效率的补弹路径。

## 已确认规则
- 普攻、跳攻、枪反等非处决击杀：跨多次攻击累计，每击杀三名敌人回复一发杀伤弹，完成奖励后进度归零。
- 同一攻击击杀四名：回复一发，剩余进度一名；每名敌人只在存活转为死亡时计数。
- 处决击杀：直接回复一发，不增加、不清空普通击杀进度，不叠加普通击杀奖励。
- 处决未击杀、伤害被无敌拒绝、失去目标、中途取消：没有处决回弹。
- 满仓仍消耗完成的奖励，不存储超容量弹药；不足门槛的进度继续保留。
- 新的一次开局填满三发，累计进度归零。杀伤弹与 Dash 推进弹独立。

## 配置与调试入口
SampleScene → Player → Player_LethalAmmo：
- Kills Per Round：非处决击杀门槛，默认 3，至少 1；可改为 2 或 4 做平衡实验。
- Kill Progress：当前累计进度，便于 Play Mode 在 Inspector 查看。
- Current Ammo：现有杀伤弹数量，仍驱动原 HUD。

## 代码与知识点
Player_LethalAmmo.RecordKill 接收击杀类型，统一处理计数及容量限制。处决分支的 return 防止同一奖励继续走普通累计分支。
Enemy_Health 继续只在存活转为死亡时发通知，避免尸体重复命中刷弹或进度。非玩家来源不触发玩家奖励。
TakeExecutionDamage 是处决专用伤害入口，临时标记此次调用并复用已有扣血流程与冲击 0；不通过玩家当前是否处决来推断伤害来源。
try/finally 保证这次伤害结算结束后恢复来源标记，即使回调抛出异常也不会污染之后的伤害分类。
Player_Execution 删除原“伤害生效回复”逻辑，只通过处决入口造成伤害。最终致死奖励经 Enemy_Health 转交弹仓，只有一个奖励结算位置。
SampleScene 仅给现有弹仓组件明确保存 killsPerRound=3、killProgress=0，其他场景文档内容保持本次修改前一致。

## 自动检查
四个实际写入文件与候选哈希一致，场景 document ID 唯一。采用项目 Unity 编译参数编译游戏脚本：0 错误、6 项既有警告。351 项隔离断言通过，其中包含更新后的既有功能回归及新奖励规则、群体击杀、尸体重复命中、处决期间的其他击杀、伤害拒绝、异常标记恢复、HUD 和推进弹独立性检查。
隔离检查使用 Unity 类型适配器，不运行真实 Unity 物理、Animator 或协程；真实 Play Mode 尚待手动验证。

## Unity 验证步骤
1. 等待导入编译，确认 Console 无新增错误，进入 SampleScene 的 Play Mode。先消耗弹药留出空位。
2. 在同一次运行中用非处决攻击击杀第一名、第二名，查看 Kill Progress 分别为 1、2，弹药不回复；第三名后进度归零且回复一发。
3. 先累计两名，再处决击杀：仅回复一发且进度仍为 2；之后非处决击杀一名再回复一发并归零。
4. 处决未杀死敌人：弹药与进度不变；对尸体继续攻击也不改变弹药或进度。
5. 同一攻击击杀多名，核对每名只累计一次，门槛三名。枪反扣弹照旧。
6. 核对上半弹巢显示真实杀伤弹，下半推进弹及 Dash 补弹保持正常。
7. 满仓时完成第三名普通击杀：仍为三发且进度归零，随后开枪不会自动发放刚才超出的奖励。
