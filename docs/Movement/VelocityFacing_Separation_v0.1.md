# 玩家速度与朝向分离 v0.1：原因、实现过程与验证

日期：2026-11-19（Asia/Shanghai）。任务：MOVE-003。用户确认按此前方案修改，并要求将原因和过程记录为 Markdown，供后续整理到 GitHub。当前状态：本地实现、技术验证与归档完成，玩家手感待验收。本次 GitHub 仅发布历程与清单；源码、场景、报告和备份包待第一个关卡完成后再同步。

## 1. 为什么修改

玩家开启 Movement Feel 总开关后，在部分墙边反复左右翻面；关闭总开关则没有这个现象。复现组合为总开关开启、Smooth Movement 关闭，向合并碰撞体墙面持续输入。

原来的 `Entity.SetVelocity(x, y)` 同时做两件事：设置刚体速度，再调用 `HandFlip(x)`。后者只按正负确定面朝方向。这样的写法适合早期“向哪里移动就朝哪里”的原型，但无法区分操作输入、动作位移、惯性和碰撞残余。

独立 Unity 副本的复现记录：150 帧内翻面 43 次。高精度水平速度为 `-5.48733388E-14`，视觉上已经静止，但负号仍触发向左翻面；下一帧右方向输入又设置 `8` 的速度并翻回右边。调用链为：

```text
Player.FixedUpdate
→ Player_MovementController.FixedTick
→ Entity.SetVelocity
→ Entity.HandFlip
→ Entity.Flip
```

刚体 Inspector 的普通显示精度会把这个值显示成接近 0，因此必须记录高精度数值与调用栈。`Input Dead Zone` 过滤输入，无法过滤碰撞产生的速度。

## 3. 第一阶段：拆开执行入口

在 `Assets/Scripts/Player/Player.cs` 增加三个方法和一个只读属性：

| 入口 | 职责 |
| --- | --- |
| `ApplyVelocity(float xVelocity, float yVelocity)` | 只写刚体速度，保留原 `isKnocked` 受击保护，不翻面 |
| `SetFacingDirection(int direction)` | 按明确方向调用原 HandFlip，沿用 Flip 和 OnFlipped；暂停、受击、死亡等情况拒绝转向 |
| `UpdateFacingFromInput()` | 将当前有效横向输入交给朝向入口；无输入保持原朝向 |
| `InputFacingDirection` | 复用 Input Dead Zone，将有效横向输入归一成 -1 / 0 / 1 |

`Entity.SetVelocity()` 保持原样，供敌人兼容。玩家运行时及其验证入口不再调用旧组合方法。没有使用 C# 方法隐藏来改变相同方法名在不同静态类型下的行为。

新玩家入口继续使用原根节点翻面，确保 `facingDirection`、攻击检测点、墙体射线方向及 `OnFlipped` 血条通知同步；没有拆分或替换现有美术层级。

C# 知识：把一个函数附带修改的状态减少后，调用者更容易判断它会产生什么效果。设置速度现在只负责运动，动作状态负责决定何时转向。

## 4. 第二阶段：普通移动与检测时序

`Player.Update()` 仅对普通 Idle / Move / Jump / Fall 和墙跳开放输入转向，并在 Entity 刷新墙体射线前完成。其他动作没有全局输入转向权限，避免普通方向键覆盖攻击和 Dash 的锁向。

`Player_MovementController.FixedTick()` 保留原加速度、重力、土狼时间、输入缓冲、斜坡和下落限速，只将最终调用改为 `ApplyVelocity()`。真实物理速度保留，微小碰撞残余不再具有改变朝向的权限。

普通反向输入采用“立即转向，身体继续按加速度制动再折返”。无输入时保持朝向，惯性和坡面贴地速度不会重新决定面朝方向。Movement Feel / Smooth Movement 的四种组合共用这套朝向规则；总开关继续决定普通移动和跳跃的物理分支。

旧版 `PlayerMoveState` 切换 Idle 后增加 return，并仅阻止朝墙输入。这样不会切完状态又继续向墙写速度，反向离墙仍可使用。Idle、Aired、Jump 的速度调用一并迁移。

Unity 知识：输入意图与碰撞后的刚体速度可以不同。Update 处理输入与状态权限，FixedUpdate 推进物理；一次物理回写不应暗中覆盖动作意图。

## 5. 第三阶段：逐个迁移动作

| 文件 / 状态 | 本次调整原因与处理 |
| --- | --- |
| `Player_WallSlideState.cs` | 保存进入时的墙侧；向外输入立即转 Fall 并更新朝向。落地按输入 / 原朝向处理，移除无条件 Flip；切走后 return |
| `Player_WallJumpState.cs` | 先缓存推出方向，再设置朝向与初速度；物理步只调整 X，保留 Y。原即时控制和 0.15 秒防重新贴墙规则保留 |
| `Player_DashState.cs` | 起手显式确定并设置冲刺朝向，后续只写速度；无输入沿当前朝向，反向输入不能中途改向，喷射方向继续与冲刺相反 |
| `Player_AttackState.cs` | 起手显式锁定 attackDir；输入归一为 ±1，避免将模拟输入直接转 int 得到 0。第二段 X=0 的攻击也能转向，后退位移可保持攻击面向 |
| `Player_ClimbState.cs` | 上下移动只写速度；跳离 / 横向离梯时按输入明确设置朝向，保留重力与碰撞恢复流程 |
| `Player_HeavyChargeState.cs` | 通过统一输入入口调整朝向，蓄力仍原地可转向 |
| `Player_HeavyAttackState.cs` | 释放时通过朝向入口锁向，直接写 X 的强制位移继续独立，不随负距离翻身 |
| 枪反、空中攻击、停步辅助 | 速度停止调用迁移，保留现有起手朝向和动画事件 |
| 重击收招、处决、死亡 | 保留现有状态接管；普通输入不获得转向权限 |
| 敌人 | 保留 SetVelocity 兼容；后退与候战已有独立设速度 / 面向目标的实现，不迁移敌人 FSM |

实现沿用现有文件分类、字段 camelCase、方法 / 属性 PascalCase 与 Enter / Update / Exit 写法，没有新增 FSM 状态或 MonoBehaviour 组件。

## 7. 调试与验收方法

普通移动反向输入时，观察角色先转面，再完成身体制动。松手仍滑行时应保持最后面向。两侧墙都测试持续顶墙、反向离开、跳起、墙滑和墙跳；四种开关组合都应稳定。

普攻第二段在原地换向后起手，确认动画与判伤朝向一致；将测试对象的攻击位移临时设为负数，应后退但保持攻击面向。Dash / 重击出刺期间按反方向，朝向应保持锁定。Play Mode 临时改值不会在退出后保存。

方向输入死区继续在 `Player → Movement Feel → Input Dead Zone` 调整。动作能否转向由相应 FSM 状态决定；本次没有新增 Inspector 字段，也不覆盖场景中已有移动数值。
